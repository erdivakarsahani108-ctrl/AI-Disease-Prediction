## How the Data Quality Score is calculated

Starting from 100, transparent penalties are subtracted (see
`compute_quality_score()` in `scripts/validate_dataset.py`):

| Penalty | Formula | Max penalty |
|---|---|---|
| Missing values | `missing_value_pct * 2` | 20 |
| Duplicates | `duplicate_pct * 3` | 15 |
| Invalid records | `invalid_record_pct * 3` | 15 |
| Class imbalance | `(imbalance_ratio - 5) * 1.2` (only if ratio > 5) | 25 |
| Synthetic-data proportion | `(synthetic_pct - 50) * 0.3` (only if > 50%) | 15 |

Current score: 100 - 0 - 0 - 0 - 25 (imbalance capped) - 15 (synthetic capped) = **61/100**.

This score is intentionally **not inflated** - it honestly reflects that
(a) the dataset is heavily class-imbalanced due to real data scarcity for
several diseases, and (b) the majority of records are synthetically
augmented (see `docs/dataset_methodology.md` for why, and why this is not
considered fabrication).

## Ambiguous symptom patterns (not a defect)

335 symptom-pattern groups in the dataset map to more than one disease -
i.e., several diseases can genuinely present with an identical symptom
set (e.g. early-stage viral infections often share fever + fatigue +
headache). This is flagged explicitly because it is a **real diagnostic
ambiguity**, not a data-cleaning bug, and is one reason the system always
returns a differential Top-K list rather than a single answer.
