# Dataset Methodology

This document explains, step by step, exactly how
`data/processed/disease_dataset.csv` (10,301 records, 41 diseases, 131
symptom features) was built from the raw public source files, and why.
The full implementation lives in `src/preprocessing/` and is orchestrated
by `scripts/prepare_data.py` (reproducible with a fixed random seed).

## Step 1 - Load & clean raw source data

1. `dataset.csv` (4,920 rows, up to 17 symptom slots/row) is melted into
   (disease, symptom) pairs.
2. Every symptom token is standardized via `clean_symptom_token()`:
   lowercased, whitespace/hyphens converted to underscores, multiple
   underscores collapsed, NaN/empty values dropped.
3. Two known spelling inconsistencies between `dataset.csv` and
   `Symptom-severity.csv` are corrected to a single canonical token (see
   `SYMPTOM_TOKEN_CORRECTIONS` in `src/preprocessing/clean.py`).
4. Rows are grouped into `(disease, sorted-symptom-tuple)` and exact
   duplicates removed -> **304 unique real combinations** remain (4,616
   of the original 4,920 rows were exact duplicates of another row for
   the same disease).

## Step 2 - Why synthetic augmentation was necessary

304 real unique records across 41 diseases (~7 per disease on average) is
too small and too imbalanced for stable multi-class ML training, and far
below the ~10,000-record target for this project.

## Step 3 - Synthetic augmentation methodology (no fabrication)

For each disease, the **union of all symptoms ever observed for that
disease** in the real data is computed (`build_disease_symptom_pool`).
This "pool" is the *only* universe of symptoms a synthetic record for that
disease may draw from - **no symptom is ever added to a disease that was
not already validated for it in the real source data**.

New synthetic records are generated by:
1. Sampling a random subset size (>=2 symptoms, up to the full pool size).
2. Randomly sampling that many symptoms from the disease's real pool
   (`random.Random(seed=42)` for full reproducibility).
3. Rejecting any subset already produced (real or synthetic) for that
   disease, guaranteeing no duplicate rows.
4. Repeating per disease until it reaches `TARGET_RECORDS_PER_DISEASE = 600`
   total records (real + synthetic combined) **or** the disease's
   combinatorial capacity is exhausted (some diseases have very few
   possible non-duplicate symptom subsets, e.g. a 5-symptom pool has only
   26 possible subsets of size >= 2 - see the per-disease capacity table
   below).

Every generated record is stamped:
- `source = "synthetic_augmentation"`
- `synthetic_flag = True`

Real records are stamped:
- `source = "kaggle_disease_symptom_dataset"`
- `synthetic_flag = False`

**Real and synthetic records are always distinguishable** via the
`synthetic_flag` / `source` columns, as required.

## Step 4 - Resulting dataset characteristics

| Metric | Value |
|---|---|
| Total records | 10,301 |
| Real records | 304 (2.95%) |
| Synthetic records | 9,997 (97.05%) |
| Diseases | 41 |
| Symptom features | 131 |
| Class imbalance ratio (max/min) | 54.55 : 1 |
| Min / Max records per disease | 11 / 600 |

Because several diseases have inherently small real symptom pools (e.g.
"Fungal infection" has only 5 validated real symptoms -> at most 26
distinguishable subsets), those diseases remain under-represented **by
design** - increasing the target further would force either exact
duplicate rows or fabricated symptom associations, both of which this
project explicitly avoids. This honest limitation is documented in
`docs/data_quality_report.md` and `docs/limitations.md`, and is
compensated for during training via `class_weight="balanced"` and
macro-averaged evaluation metrics (see `docs/model_evaluation.md`).

## Step 5 - Feature engineering

Each record is one-hot encoded across all 131 canonical symptom columns
(1 = symptom present, 0 = absent), plus `disease`, `disease_category`
(curated taxonomy), `symptoms` (human-readable string), `symptom_count`,
`source`, and `synthetic_flag`.

## Step 6 - Validation

`scripts/validate_dataset.py` / the `validate()` function in
`scripts/prepare_data.py` check for: missing disease labels, zero-symptom
rows, fully duplicate (disease + symptom-pattern) rows, and class
imbalance ratio - any issue found is logged in
`docs/data_dictionary.md` under "Data Quality Notes".

## Reproducibility

Running `python scripts/prepare_data.py` again with the same
`RANDOM_SEED = 42` (see `src/utils/paths.py`) reproduces the exact same
`data/processed/disease_dataset.csv` byte-for-byte (verified via the
`dataset_version_hash` recorded in `models/model_metadata.json`).
